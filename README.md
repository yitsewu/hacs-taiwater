# 台灣自來水公司：Home Assistant／HACS 整合

版本：`0.2.0`，初版測試套件，最低 Home Assistant `2026.9.1`。適用台灣自來水公司水費查詢；不適用臺北自來水事業處。

輸入水號與戶名後，由 HA 直接查詢官方網站，提供帳單、歷史分攤、排程與狀態感測器。HAOS 可搭配同一個 repository 的「台水 OCR」附加元件，在自己的主機辨識圖片。

## 安裝

正式 HACS 自訂 repository 安裝需要本 repository 對該使用者可見；尚未公開的開發版本請先用 ZIP 手動安裝。這不是 HACS 預設目錄的審核通過宣告。

1. HAOS：在「設定 → 附加元件 → 附加元件商店 → 儲存庫」加入 `https://github.com/yitsewu/taiwater-hacs`，安裝並啟動「台水 OCR」。完成後開啟隨系統啟動。詳見 [OCR 說明](taiwater_ocr/README.md)。
2. HACS：「自訂儲存庫」加入相同網址，類型選 Integration，下載「台灣自來水公司」並重新啟動 HA。手動方式則將 ZIP 內的 `custom_components/taiwater` 放入 HA `/config/custom_components/`。
3. 「設定 → 裝置與服務 → 新增整合 → 台灣自來水公司」，填水號、戶名及顯示名稱。HAOS 會尋找已安裝的台水 OCR 附加元件；一般不需設定網址。
4. 完成設定後，在整合的設定選項調整排程、歷史期數、分攤方式與碳排係數。

初版使用 Home Assistant 長期統計 API；自動測試版本見 CI。未實機驗收的 HA 版本或 CPU 架構不宣稱已支援。Home Assistant Container 使用者可自行啟動 OCR container，於整合中填寫 HA 可到達的內網 OCR URL；不需要 Windows 查詢服務。

## 設定

| 設定 | 預設／行為 |
| --- | --- |
| 水號、戶名 | 必填；水號保留前導零，允許顯示用連字號 |
| 顯示名稱 | 台灣自來水公司；可改為房屋名稱，多水號分別新增整合 |
| 自動查詢 | 每週一 09:00，使用 HA 設定時區 |
| 查詢排程 | 每日、每週或每月指定日期／時間；月末不存在的日期使用該月最後一天 |
| 首次歷史期數 | 0＝原站提供的全部帳期；也可設定最近 N 期 |
| 分攤方式 | 按實際計費期間天數；另可選涵蓋月份等額分攤 |
| 碳排係數 | 未設定；單位 kgCO2e/m³，設定時須填來源／適用年份 |
| OCR 網址 | 空白＝自動尋找 HAOS 附加元件；找不到時嘗試本機已存在的 OCR 套件 |

排程更新只補齊尚未保存的帳期，並重新查最新一期。「補抓歷史」會重新查設定範圍內的帳期，用於回填或更新修正過的舊帳單。原站日後移除舊帳期，不會刪除已保存的資料。

## HA 提供的資料

- 最新帳期、用水度數、原始應繳總金額、原站費用細項及可取得的日期。
- 最新有資料月份的分攤用水／費用／碳排、年度已取得資料合計與涵蓋月份數。
- 上次查詢時間、上次成功時間、上次失敗時間、下次排程時間。
- 查詢結果、OCR 辨識結果、原站驗證結果、錯誤碼、已匯入與可查帳期數、歷史完整性與統計寫入狀態。
- 「立即查詢最新一期」、「補抓歷史」按鈕與「自動查詢」開關。
- 若原站提供付款狀態就顯示；沒有資料時為未知，不推測已繳或未繳。

OCR 的 `success` 只表示辨識出格式有效的文字，不等於原站接受。原站明確拒絕驗證碼時，會同時出現「OCR 成功」與「驗證失敗」。網路失敗或回應不明時，不捏造驗證結果。完整查詢失敗不更新最後成功時間；歷史部分失敗保留已取得的有效帳單並標示 `partial`。

## 查詢紀錄與指定帳期補抓

在 HA「開發者工具 → 動作」可使用以下動作；也可加入自己的 script／自動化。`config_entry_id` 在介面選擇台水帳戶，YAML 範例則替換為該整合的設定項目 ID。

```yaml
action: taiwater.get_query_history
data:
  config_entry_id: YOUR_CONFIG_ENTRY_ID
  limit: 25
response_variable: query_history
```

每個帳戶保留最近 **100 次**查詢，最新紀錄在前。記錄查詢 ID、觸發方式（setup／initial／schedule／button／manual／action）、操作（initial／latest／history／month）、指定帳期、開始／完成時間、耗時秒數、結果、OCR 結果、台水驗證結果、固定錯誤碼與取得帳單數。`fetched_count` 是取回數量，不代表通過格式檢查或新增的帳單數。

紀錄隨 HA 重啟保留；未完成的查詢標成 `interrupted`，完成時間是啟動時辨識中斷的時間，未知耗時留空。首次設定匯入的結果也會記錄，但未量測的耗時留空。升級前的逐次歷程無法回補。無效輸入或忙碌時拒絕的請求尚未開始查詢，不增加紀錄。讀取紀錄不連線台水，也不保存姓名、水號、驗證碼文字／圖片、Cookie 或原始錯誤內容。

```yaml
action: taiwater.query_month
data:
  config_entry_id: YOUR_CONFIG_ENTRY_ID
  month: "2026-08"
response_variable: queried_bill
```

指定的是**原站帳期**，不是分攤後的月份。可從 `taiwater.get_history` 的 `available_months` 取得最近已知清單。此動作重新建立工作階段、執行 OCR／驗證，再取得指定帳期；原站驗證流程可能先回傳預選帳期，但只保存要求的那一期。不需要重抓其他歷史，也不改動下次排程。

回應包含 `query` 查詢紀錄及 `bill` 正規化帳單；`response_variable` 可省略。同帳期更新後會重建本整合的分攤統計，不重複累加。不存在的帳期回報 `month_unavailable`；查詢失敗保留原帳單，原因可由查詢紀錄讀取。OCR 失敗沿用既有人工查詢備援。

## 費用、碳排與歷史統計

原始帳單始終保留。月度／日度／小時數值都是**帳單分攤估算**，不是即時水表讀值，也不是付款日期的現金流。

- 原站「本期計費用水期間」包含開始與結束日。按日模式依各月實際涵蓋天數分攤；等額模式先在涵蓋月份之間等分，再分配到該月涵蓋日期。
- 費用直接分攤原始總額，不重新套用單月水價。加退款可為負數，細項不重複加入總額。
- 缺少計費日期時，月度列表使用「帳單月份＋前一月」的明確估算；不偽造實際抄表日期，也不為這部分產生日度長期統計。
- 碳排優先使用原站明確提供的 kgCO2e 數值；沒有時才套用使用者設定的係數。未設定係數顯示未知。係數應註明來源、年份、供水範圍；不代表家庭熱水、污水處理等全部碳排。
- 年度合計僅涵蓋已取得資料。尚無帳單的月份不補零；不得將部分年度合計當作完整年度。
- 不為「每期用量」設定不適用的 `total_increasing`。整合另以 `taiwater:<entry_id>_water`、`_cost`、`_carbon` 保存分攤長期統計，其中費用固定 TWD，不隨 HA 顯示幣別變成其他貨幣。
- 可在 HA 能源設定選取對應的外部水量統計及費用統計。碳排提供獨立統計，不冒充能源面板的電網碳強度。實際 UI 可選擇性以相應 HA 版本驗收為準。
- 同帳期以最新成功結果更新，不重複累加。區間重疊或格式不符時拒絕寫入。修正歷史或分攤設定後，從已保存帳單重建**本整合自己擁有的三個統計 ID**；不清除其他整合資料。

## Cookie 與人工備援

每次新查詢建立自己的 Cookie 工作階段，取得原站驗證碼及 CSRF token。OCR 只處理圖片，HA 使用同一工作階段完成水號／姓名驗證及帳期切換，並沿用原站更新後的 token。使用者不用複製 Cookie。

驗證失敗不無限重試；本次記錄失敗，下次重新建立 session。HA 重啟後 session 不保留。OCR 不可用時，可在設定流程或整合選項的「人工查詢」查看圖片並輸入驗證碼。

驗證碼圖片透過三分鐘失效的隨機能力網址供設定介面讀取，不包含帳戶資料，送出後即失效；不寫入磁碟。對外提供 HA 時應使用 HA 自己的 TLS／登入保護。

## 保存、隱私與回復

水號與戶名存於 HA 原生 config entry；帳單與查詢狀態存於 `/config/.storage/taiwater.<entry_id>`，HA Recorder 保存統計。不把水號、戶名、銀行代繳帳號或地址放入 entity/device ID、診斷下載、程式碼或日誌。

Cookie、CSRF token、驗證碼文字／圖片與原始 HTML 只留在記憶體。OCR 不收水號或戶名；附加元件預設不對外開放連接埠。請將 HA 備份視為含私人設定與帳單的資料保管。

停用排程不會刪帳單；移除整合前請先備份 HA。解除載入不清除保存資料或外部統計。回退版本時恢復已驗證的程式 ZIP 與必要 HA 備份，勿手動修改 Recorder 資料庫。

## 開發驗證

```shell
python -m pip install pytest pytest-asyncio tzdata Pillow ruff
pytest tests --ignore=tests/ha -q
ruff check custom_components tests scripts taiwater_ocr
python scripts/package.py
```

Linux／Python 3.14 的完整 HA 測試使用 `pytest-homeassistant-custom-component==0.13.364`，執行 `pytest tests/ha -v`。CI 同時驗證 HACS 目錄結構、hassfest、OCR container 模型載入與去識別測試。測試不登入真實帳戶，不保存原始帳單。

查詢 parser 由既有本機台水工具整理而來；OCR 依賴透過套件管理器安裝，相關第三方程式遵循原授權。
